What is the Preprocessor?

The preprocessor is the first stage of compilation. It processes all preprocessor directives (lines starting with #) before actual compilation begins.

Input & Output

Input: .c (C source files)

Output: .i (Preprocessed source files)

What Does It Do?

  • Removes comments: All /* */ and // comments are stripped out
  • Includes header files: Replaces #include directives with actual file contents
  • Expands macros: Replaces all #define macros with their values
  • Conditional compilation: Processes #ifdef, #ifndef, #if, etc.

Example

// Before preprocessing (hello.c)
#include <stdio.h>
#define PI 3.14159

int main() {
    printf("Pi is %f\n", PI);
    return 0;
}

// After preprocessing (hello.i)
// ... (entire stdio.h contents inserted here) ...

int main() {
    printf("Pi is %f\n", 3.14159);
    return 0;
}

Run Manually

gcc -E source.c -o source.i

The -E flag stops after preprocessing

What is the Compiler?

The compiler (proper) translates preprocessed C code into assembly language. This is where the actual compilation happens.

Input & Output

Input: .i (Preprocessed source)

Output: .s or .asm (Assembly code)

What Does It Do?

  • Lexical analysis: Breaks code into tokens (keywords, identifiers, operators)
  • Syntax analysis: Checks if code follows C grammar rules
  • Semantic analysis: Type checking, variable declarations, etc.
  • Optimization: Improves code efficiency (various levels: -O0, -O1, -O2, -O3)
  • Code generation: Generates assembly code for target architecture

Example

// C code (from .i file)
int add(int a, int b) {
    return a + b;
}

// Generated assembly code (.s file)
add:
    push    rbp
    mov     rbp, rsp
    mov     DWORD PTR [rbp-4], edi
    mov     DWORD PTR [rbp-8], esi
    mov     edx, DWORD PTR [rbp-4]
    mov     eax, DWORD PTR [rbp-8]
    add     eax, edx
    pop     rbp
    ret

Run Manually

gcc -S source.i -o source.s

The -S flag stops after compilation (generates assembly)

What is the Assembler?

The assembler converts human-readable assembly language into machine code (binary) that the processor can execute.

Input & Output

Input: .s or .asm (Assembly code)

Output: .o (Object files - binary machine code)

What Does It Do?

  • Translates mnemonics: Converts assembly instructions (like mov, add) to binary opcodes
  • Resolves symbols: Creates symbol table for functions and variables
  • Generates relocatable code: Code that can be placed anywhere in memory
  • Creates object file: Binary file with machine code, but not yet executable

Object File Contents

An .o file contains:

  • Machine code instructions
  • Symbol table (function/variable names and addresses)
  • Relocation information
  • Debug information (if compiled with -g)

Example

// Assembly (.s file)
mov eax, 5

// Machine code (.o file) - hexadecimal representation
B8 05 00 00 00

Run Manually

gcc -c source.s -o source.o

as source.s -o source.o (using GNU assembler directly)

The -c flag compiles without linking

What is the Linker?

The linker is the final stage. It combines multiple object files and libraries into a single executable file.

Input & Output

Input: .o (Object files) + .so / .a (Libraries)

Output: .exe (Windows) or executable (Linux/Mac)

What Does It Do?

  • Resolves symbols: Connects function calls to their definitions across multiple files
  • Combines object files: Merges all .o files into one executable
  • Links libraries: Includes code from standard library (libc) and other libraries
  • Assigns addresses: Determines final memory addresses for all code and data
  • Creates executable: Produces final runnable program

Types of Linking

Static Linking: Library code is copied into the executable (larger file, no external dependencies)

Dynamic Linking: Executable references external shared libraries (smaller file, requires .so or .dll files at runtime)

Example

// You have two files:
// main.o - contains main() function, calls add()
// math.o - contains add() function definition

// Linker combines them and resolves:
// "Where is add()?" → "It's in math.o at address 0x1234"

// Result: Single executable with both functions

Run Manually

gcc main.o math.o -o program

ld main.o math.o -o program (using GNU linker directly)

Common Linker Errors

  • Undefined reference: Function called but never defined
  • Multiple definition: Same function defined in multiple files
  • Library not found: Missing -l flag for required library
