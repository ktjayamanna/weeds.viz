What is the Stack?

The stack is a LIFO (Last In, First Out) data structure used for:

  • Local variables
  • Function call frames
  • Function parameters
  • Return addresses
  • Saved register values

Growth Direction

The stack grows downward toward lower memory addresses. Each function call pushes a new frame onto the stack.

Per-Thread Allocation

Important: Each thread gets its own stack (typically ~8MB). The stack shown is specific to the main thread. Other threads get ~8MB of stacks carved out from heap and other areas.

Size

Typical stack size: 8MB per thread (Linux default)

Can be changed with ulimit -s or pthread_attr_setstacksize()

What is the Heap?

The heap is used for dynamic memory allocation at runtime:

  • Memory allocated with malloc(), calloc(), realloc()
  • Python objects (when using CPython)
  • C++ objects created with new
  • Memory that needs to persist beyond function scope

Growth Direction

The heap grows upward toward higher memory addresses.

Shared Across Threads

Important: Unlike the stack, the heap is shared among all threads in a process. This is why you need synchronization (mutexes, locks) when multiple threads access heap memory.

Management

Memory must be manually freed with free() or delete, or it's handled by garbage collectors in languages like Python, Java, etc.

Size

The heap can grow dynamically (limited by system memory and virtual address space).

What is BSS?

BSS stands for "Block Started by Symbol"

This section contains uninitialized global and static variables.

Contents

  • Uninitialized global variables
  • Uninitialized static variables
  • Variables explicitly initialized to zero

Example

int global_var; // Goes in BSS

static int counter; // Goes in BSS

int zero_var = 0; // Also goes in BSS

Why Separate from Data?

All BSS variables are initialized to zero by the OS. By keeping them separate, the executable file doesn't need to store all those zeros, saving disk space.

What is the Data Section?

This section contains initialized global and static variables.

Contents

  • Initialized global variables
  • Initialized static variables (both local and global)
  • Any global/static data with non-zero initial values

Example

int global_var = 42; // Goes in Data

static int counter = 100; // Goes in Data

char* msg = "hello"; // Pointer in Data, string in Read-Only Data

Writable

Unlike the Read-Only Data section, this section is writable. Values can be modified at runtime.

Stored in Executable

Initial values are stored in the executable file and loaded into memory when the program starts.

What is Read-Only Data?

This section contains constant data that should never be modified.

Contents

  • String literals (e.g., "Hello, World!")
  • Constant global variables (const in C/C++)
  • Numeric constants
  • Jump tables for switch statements

Example

const char* str = "Hello"; // "Hello" in Read-Only Data

const int PI = 3.14159; // PI in Read-Only Data

Memory Protection

This section is marked as read-only by the OS. Attempting to modify it will cause a segmentation fault (crash).

Security Benefit

Making this section read-only prevents certain types of exploits where attackers try to modify program constants.

What is the Text Section?

This section contains the executable machine code of your program.

Contents

  • Compiled machine instructions
  • All function code (your code + library code)
  • Python bytecode (in CPython's case)
  • Executable instructions that the CPU runs

Example

Your C function:

int add(int a, int b) { return a + b; }

Gets compiled to machine code stored here.

Read-Only and Executable

This section is marked as read-only and executable. You can't modify code at runtime (security feature).

Shared Across Processes

Multiple instances of the same program can share the same Text section in memory (code doesn't change).

Size

Fixed at compile time. Determined by the size of your compiled code and linked libraries.
